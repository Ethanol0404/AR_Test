# Liver AR Visualisation Prototype

This Unity project is an Android AR prototype for:

Semiautomatic Segmentation and 3D Reconstruction of the Liver Using Medical Images for Augmented Reality Visualisation.

The Unity app visualises reconstructed liver anatomy. It does not perform CT/MRI segmentation, DICOM processing, medical diagnosis, or treatment planning.

Visible in-app disclaimer:

"This application is an educational prototype and is not intended for clinical diagnosis or treatment planning."

- `Assets/LiverAR/Models/SourceFrom3DSlicer`: copied source exports from folder `5`.

- `Assets/Scenes/LiverARScene.unity`: generated by the setup utility.

## Source Assets From Folder 5

The attached `5` folder contains:

- `Segment_1.obj` and `Segment_1.mtl`: Unity-importable mesh/material files.
- `*.vtk`: 3D Slicer/VTK mesh exports. Unity does not import these directly by default.
- `*.seg.nrrd`: 3D Slicer segmentation source files. These are not Unity runtime meshes.
- `2026-07-09-Scene.mrml` and `.png`: 3D Slicer scene/reference files.

The initial Unity setup uses `Segment_1.obj` when Unity imports it. Other anatomical structures are generated as clearly named placeholders so the AR controls can be tested before all final meshes are exported.

## Generate The Initial AR Scene

Open the project in Unity, then run:

`Liver AR > Generate Initial AR Scene`

This creates:

- `Assets/LiverAR/Configs/LiverAnatomyConfig.asset`
- `Assets/LiverAR/Prefabs/LiverAnatomyPrototype.prefab`
- `Assets/Scenes/LiverARScene.unity`

It also adds `LiverARScene` to Build Settings.

## Architecture Overview

- `ARPlacementController`: places one liver model on a detected horizontal AR plane and disables distracting plane visualisation after placement.
- `ModelInteractionController`: one-finger plane repositioning, one-finger horizontal rotation fallback, two-finger pinch scaling, and transform reset.
- `AnatomyPart`: stable ID, display name, category, colour, renderer references, visibility, opacity, and selection highlight.
- `AnatomyManager`: registers structures, manages selection, show/hide all, and appearance reset.
- `AnatomySelectionController`: raycasts from touch to colliders and selects anatomical parts.
- `TransparencyController`: clamps and applies opacity to the selected structure.
- `ARUIController`: connects mobile UI controls to runtime logic.
- `ARSessionResetController`: resets placement and AR session state.
- `ARStatusController`: shows user-facing AR availability/tracking messages.
- `AnatomyModelConfig`: inspector-editable structure definitions.

## Interaction Model

- Move device slowly until a horizontal plane is detected.
- Tap a detected plane to place exactly one liver model.
- One-finger drag over a detected plane repositions the model.
- One-finger horizontal movement rotates the model when plane repositioning is not available.
- Two-finger pinch scales uniformly within safe limits.
- UI touches block model gestures.
- Reset Model restores the transform captured at placement.
- Reset AR removes the placed model and restarts AR placement.

## Preparing 3D Slicer Models

For independent structure control, export each anatomical structure as a separate mesh:

1. In 3D Slicer, keep liver segments, vessels, and lesions as separate segmentation/model nodes.
2. Export each structure as OBJ, or convert/export to GLB/glTF.
3. Use clear names such as `Segment_I.obj`, `Segment_IVa.obj`, `Portal_Vein.obj`.
4. Preserve the shared coordinate system so all structures stay aligned.
5. Import the mesh files into `Assets/LiverAR/Models`.
6. Correct orientation and scale only at the common model root when possible.
7. Place every structure under one common prefab root.
8. Add or verify colliders for selection. Prefer simple colliders where accurate enough.
9. Assign each object to an `AnatomyPart` with stable ID, display name, category, and colour.
10. Update `AnatomyModelConfig.asset` and the prefab.

Do not merge structures if they need independent visibility, selection, colour, or transparency.

## GLB/glTF Workflow

This initial implementation does not install a glTF package. If GLB/glTF files are required, add a Unity 6000-compatible importer such as glTFast through Package Manager, then convert imported files into normal prefabs and assign `AnatomyPart` components the same way as OBJ meshes.

## Testing

Automated tests:

- `Assets/LiverAR/Tests/EditMode/LiverARLogicTests.cs`

Manual Android test checklist:

1. Build and install on an ARCore-compatible Android phone.
2. Confirm camera permission prompt appears.
3. Deny permission once and verify the app fails gracefully.
4. Relaunch and allow permission.
5. Move device slowly and confirm plane detection guidance.
6. Tap a horizontal surface and confirm only one model is placed.
7. Try repeated taps and confirm duplicate placement does not occur.
8. Drag the model on a horizontal plane.
9. Rotate the model with horizontal movement when repositioning is not active.
10. Pinch to scale; confirm min/max limits prevent inversion or extreme sizes.
11. Select every available anatomical structure.
12. Confirm selected name and category update.
13. Hide and show the selected structure.
14. Use Show All and Hide All.
15. Adjust selected structure transparency.
16. Confirm no transparency change occurs when nothing is selected.
17. Change selected structure colour with the prototype colour button.
18. Reset Appearance.
19. Reset Model Transform.
20. Reset AR Session and place again.
21. Cover camera or move quickly and observe tracking-lost behavior.
22. Check frame responsiveness with all final structures visible.

## Known Limitations

- Only `Segment_1.obj` from folder `5` is directly Unity-importable as a mesh.
- VTK and NRRD files are preserved as source exports, not rendered directly.
- The generated prefab uses placeholders for structures that need separate OBJ/GLB exports.
- Physical Android AR behavior was not verified unless this checklist is run on a real device.
- The prototype colour button applies one preset colour; a compact mobile colour picker should be added when final UI polish is needed.

## Improvement Suggestions

- Export all Couinaud segments, portal vein, hepatic vein, other vessels, and lesion as separate OBJ or GLB meshes.
- Decimate meshes in 3D Slicer/Blender while preserving thin vascular structures.
- Keep texture sizes modest for Android.
- Replace placeholder UI with a collapsible grouped structure panel once final model names are known.
- Add glTFast if GLB becomes the primary import format.
- Add a device-specific performance pass after final mesh import.
